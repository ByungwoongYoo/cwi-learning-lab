# CPU 추론: 작은 파일이 더 빠른 모델인가?

합성 데이터의 작은 MLP를 FP32와 PyTorch dynamic INT8로 비교하는 재현 실험입니다. 새 알고리즘·실서비스 성능·GPU 경험이 아니라 **조건을 고정하고 정확도·용량·지연을 함께 판단하는 엔지니어링 포트폴리오**입니다. AI 도움으로 구현했습니다.

## 실행

검증 환경: Linux x86_64, Python 3.12, PyTorch 2.6.0+cpu, NumPy 2.3.5. 의존성은 포함하지 않습니다. 기존 환경에서 프로젝트 디렉터리로 이동한 뒤:

    python -m tradeoff_lab --output my_result
    python -m unittest discover -s tests -v

매번 새 출력 경로를 사용해야 합니다. 기존 출력은 덮어쓰지 않습니다. 학습·양자화·품질 평가·벤치마크가 한 번 실행되고 result.json, 원시 timing CSV, 예측 NPZ와 환경 기록을 생성합니다. 다운로드·네트워크·서비스 가입·GPU가 필요하지 않습니다. 처음 의존성을 설치하는 과정은 이 검증의 범위가 아닙니다.

## 사전 고정한 조건

PLAN.json과 SHA256을 평가 전에 기록했습니다. 64→128→64→2, 16,706개 파라미터, Adam 15 epoch, train8,192/calibration2,048/test4,096 독립 난수 스트림을 사용합니다. 데이터 분할은 같은 합성 생성 분포의 별도 표본일 뿐 실제 현장 외부 검증이 아닙니다. calibration 표본 중256행은 shape/finite smoke에만 사용했습니다. Dynamic quantization에는 별도 관측자 교정 학습이 없고, 이 split으로 설정을 최적화하지 않았습니다.

3개 Linear를 x86 backend의 dynamic qint8로 변환했습니다. 각 batch1/32/256을 별도로 평가하며 동적 활성값 양자화 때문에 batch에 따라 예측이 달라질 수 있습니다. 각 조건 warmup20회 뒤 AB/BA순서를 번갈아 20블록×50회 측정했습니다. CPU thread1개, 이미 만들어진 float32 텐서에서 logits까지의 호출 시간입니다.

품질 허용치는 정확도 하락≤1%p AND 최대 클래스 확률차≤0.10입니다. 성능을 본 뒤 기준이나 모델을 바꾸지 않았습니다.

## 최초 실행 결과

- 같은 torch.save(state_dict) 방식의 메모리 직렬화 크기: FP32 **69,064B**, INT8 **21,554B**. 약68.8% 작습니다. 이 파일을 배포하지는 않습니다.
- 속도비 FP32시간/INT8시간 중앙값: batch1 **0.292**, batch32 **0.446**, batch256 **0.830**. 1보다 작으므로 INT8이 중앙값 기준 더 느렸습니다.
- FP32 정확도 **89.4775%**. INT8 **89.5264% / 89.5020% / 89.6729%**. 작은 차이를 유의미한 개선으로 해석하지 않습니다.
- 최대 확률차 **0.2243 / 0.2268 / 0.2608**로 사전 기준0.10을 넘었습니다. **세 조건 모두 품질 게이트 실패**.

**결론: 이번 작은 CPU 모델에서는 용량 감소만 확인했습니다. 속도 개선·출력 동등성을 확보했다고 주장할 수 없으므로 INT8 전환을 추천하지 않습니다.** 성능이 나쁜 결과도 조건과 원시 측정값을 보존하는 것이 이 프로젝트의 목적입니다.

## 무엇을 측정하지 않았나

- 표의 p50/p95는 **50회 호출의 블록 평균값 분포**이며 개별 요청 꼬리지연이 아닙니다.
- 단일 호스트·프로세스·CPU 스레드에서만 측정했습니다. 인터넷, 입출력, preprocessing, softmax, concurrent serving, 메모리 RSS, GPU, 다중 노드는 포함하지 않습니다.
- 작은 합성 MLP 결과를 큰 언어모델이나 모든 CPU/양자화 방식으로 일반화할 수 없습니다.
- AB/BA는 순서 영향을 줄이지만 호스트 부하를 통제하거나 여러 머신을 대표하지 않습니다. 반복 실행의 절대 시간은 달라질 수 있습니다.
- export된 NPZ는 pickle 없이 열 수 있는 **가중치 검사 파일**이며, 양자화 runtime이 직접 읽는 압축 실행 모델은 아닙니다. payload바이트/NPZ크기/torch직렬화크기를 별도로 보고합니다. 임의 출처의 pickle/torch 파일은 로드하지 않습니다.
- 모델 선택·튜닝·허용치 변경에 test 결과를 사용하지 않았습니다.
