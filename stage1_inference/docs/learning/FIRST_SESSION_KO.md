# 첫 예제 해설: 실패한 모델을 정직하게 보여 주는 데모

**AI가 작성한 선택적 코드·결과 해설입니다.** 독자의 이해나 독립 구현 능력을 평가한 기록이 아닙니다.

## 1. 실제 기록에서 확인한 결과

기존 프로젝트의 고정 평가 기록입니다. 정상 10개와 양성 10개를 포함한 **두 필렛의 개발 검증**이므로 현장 전체 성능으로 일반화하지 않습니다.

| 모델 | 뼈가 있는 이미지에서 경보가 나온 수 | 정상 이미지에서 경보가 나온 수 | 픽셀 Dice |
|---|---:|---:|---:|
| 항상 ‘없음’ | 0/10 | 0/10 | 0.000000 |
| 저에너지 `low` | 10/10 | 10/10 | 0.012761 |
| 두에너지 `dual` | 10/10 | 10/10 | 0.003188 |

기존 동결 평가 기록의 텍스트 발췌: [`BASELINE_RESULT.md`](../BASELINE_RESULT.md). `any alarm`은 엉뚱한 위치의 경보도 셉니다. Dice는 예측 픽셀과 정답 픽셀이 얼마나 겹치는지 보는 지표입니다.

### 해설 A — ‘100% 검출 성공’이라고 쓸 수 없는 이유

뼈가 든 10장에서 모두 경보가 났지만, 정상 10장에서도 모두 경보가 났습니다. 또 경보가 실제 뼈 위치에 있는지도 따로 확인해야 합니다. 따라서 ‘양성 이미지 경보 10/10’이라는 관찰을 ‘정확한 뼈 검출 성공률 100%’로 바꾸어 말할 수 없습니다. 항상 아무 경보도 내지 않는 모델 역시 오경보는 없지만 모든 양성을 놓치므로 유용한 해결책이라는 뜻은 아닙니다.

### 해설 B — 정보를 더 썼다고 더 좋은 모델은 아님

이 고정 실험에서는 `dual`의 Dice가 `low`보다 낮고 정상 오경보도 줄지 않았습니다. 따라서 두에너지 입력을 추가한 이 기준선이 더 좋다고 주장할 근거가 없습니다. 이것은 **이번 특성·샘플링·선형모델·임계 조합의 실패**이지, 모든 두에너지 방법이 나쁘다는 결론은 아닙니다.

### 해설 C — 테스트가 통과해도 정확한 모델이 되지는 않음

소프트웨어 테스트는 입력 검사·계산·표시가 약속대로 동작하는지 확인합니다. 모델이 현장에서 정확하고 안전하다는 보증은 아닙니다. 데모는 ‘모델 추론과 실패 분석이 실제로 동작한다’는 범위로 소개합니다.

## 2. AI가 구현·검증할 표시와 안전장치

아래는 데모의 구현·검증 기준입니다. **실제로 실행한 로그가 생기기 전에는 완료로 표시하지 않습니다.** 이미 존재하는 기능은 중복 구현하지 않고 테스트·문서와 일치하는지 확인합니다.

| 항목 | 필요한 동작 | 검증할 내용 |
|---|---|---|
| 실패 결과 표시 | 정상 오경보와 낮은 Dice를 화면에 명확히 표시 | 화면 문구·결과표가 원기록과 일치하고 ‘100% 검출’로 과장되지 않음 |
| 모델 구분 | `low`/`dual` 선택과 사용한 모델 버전을 구분 | 선택한 모델의 실제 추론이 실행되며 다른 모델 이름만 표시하지 않음 |
| 잘못된 입력 처리 | 형식·크기·유한값 등 실제 입력 경로에 맞는 검사 | 잘못된 입력은 명확히 거절되고 정상 입력은 계속 처리됨 |

원본 모델 JSON·고정 평가 결과를 덮어쓰지 않습니다. 검증 자료에 맞춰 임계를 조정한 뒤 새 독립 성능인 것처럼 보고하지 않습니다.

## 3. 추론과 학습은 다름

- **추론:** 저장된 `low`/`dual` 계수를 읽어 새 입력의 출력을 계산합니다. 데모에서 결과가 나오는 것은 이 경로의 증거입니다.
- **학습:** 데이터와 목표에 맞춰 모델의 가중치를 실제로 갱신합니다. 학습 로그·저장된 모델·복원 검사 등이 별도로 필요합니다.
- **CUDA / 멀티노드:** CPU 추론이나 웹 UI를 만들었다고 자동으로 생기는 경험이 아닙니다. 실제 GPU 커널 실행 또는 별도 머신의 분산학습 기록이 필요합니다.

## 4. 증거의 범위

구현·검증은 AI_ASSISTED, 사용자 역량은 NOT_ASSESSED입니다. 이 프로젝트는 로컬 CPU 실습이며 브라우저 UI 검증·외부 배포·GPU·멀티노드 실행을 입증하지 않습니다.
